# 自动检查与证据边界

对最终候选使用 [validate_note.py](../scripts/validate_note.py) 做只读源码检查。它不连接 Zotero、Obsidian 或网络，不修改笔记，也不自动生成验收通过记录。

## 使用方式

在 Python 编辑器中打开脚本，将顶部 `NOTE_PATH` 指向工作目录内的候选稿后运行。Python 依赖列在本技能的 [requirements.txt](../requirements.txt)，由安装器安装。

也可以在已有处理脚本中导入 `validate_note(text)` 或 `validate_file(path)`。返回 `Finding` 列表，每项含 `level`、`code`、`line` 和 `message`；行号用于定位源码。路径对象使用 `pathlib.Path`。

首次构建全文时检查完整候选；单项修复时先检查输入稿，再检查候选稿，将已有缺陷与本次新增缺陷分开登记。只修本次授权范围及必要依赖，不因扫描发现旧问题而改写无关内容。涉及对象的确定错误须修复后重验；范围外问题进入 `issues`，不宣称全篇通过。

## 检查内容

| 源码检查 | 能确认的事实 |
|---|---|
| 起始 YAML | 可解析、没有重复键、未保留废弃的 `库内参考文献` 键 |
| 块锚与本篇链接 | 已识别的块 ID 不重复，显式指向本篇块的链接存在对应定义 |
| 书目锚点 | 每条书目具有一个末尾块 ID；按 Citation Preview 1.3.0 的真实语法检查兼容性，并提示显示编号与锚点数字的差异 |
| Rich Table | 接受模板的 `---` 外包裹及无包裹的单份 YAML/JSON；v2 检查单表，v3 遍历全部工作表，逐表检查 locked、theme、非空 columns/rows，并检查紧邻数据块的表锚 |
| 显示公式 | 可识别的公式锚与公式闭合行、后续内容之间的间距符合静态约定 |

新建主文、单份 SI、多份 SI 的锚点分别采用 `^ref-N`、`^sref-N`、`^sref-src<source_token>-N`，稳定来源标记按[交接约定](pipeline-contract.md#补充材料与书目命名空间)确定。校验器的兼容语法对齐 [Citation Preview 1.3.0 的 referenceAnchor()](https://github.com/lyingTree/citation-preview/blob/165503f647590b7d9379e8b1ba72a2b9b61de049/src/bibliography.ts)。

既有 ID 与链接目标逐字保留。旧 `^ref-s1` 等插件不识别的形式报告 `warning / BIBLIOGRAPHY_PLUGIN_COMPAT`；已被插件识别、但数字后缀与显示列表序号不同的形式报告 `warning / BIBLIOGRAPHY_NUMBER`，提醒按书目身份核对，均不要求自动迁移。缺锚、重复定义、已识别链接的实际断链仍为 error。脚本只读，无法仅凭候选稿判断哪些锚点是新建的，也不替代书目身份核对。

代码示例、注释、公式内容和外部文件链接不应误判为本篇引文。Rich Table 的 title、footer、列名和单元格另作本篇链接检查；v3 包括非活动工作表。工作表内的发现含工作表序号及可用的 name/id，行号指向该工作表的源码起始处；单行 JSON 不虚构单元格行号。解析器只覆盖脚本明确实现的语法；没有报错仅表示这些源码规则没有发现问题。

仓库回归执行 `template/` 中四份完整 Templater 程序：普通 Markdown 表格生成 v2，已有 v3 经模板导入并逐工作表规范化，再把实际输出送入校验器。覆盖 `---` 包裹、v2/v3 无包裹变体、每张工作表的锁定与主题，以及第二工作表四类可见字段中的断链。测试使用内存中的应用与 HTTP 替身，PyYAML 适配 YAML 接口，不访问实际 Zotero 文献库或 Obsidian vault；不据此声称完成插件界面验收。

以下检查仍由对应技能执行，必须分别保存证据：

- 文献身份、版本、页段完整性、原文与译文一致性。
- 图像裁剪、单位数值、公式含义、表格数据与原文核对。
- 附件存在性和哈希、库内其他笔记的身份与引用目标。
- Obsidian 原生缓存的实际块范围与链接解析。
- Rich Table 插件、阅读视图及用户界面的实际呈现。

将脚本版本、候选哈希、检查时间和完整发现清单写入本次工作记录。源码、内容、写入、缓存、界面各记各的状态；静态检查通过不能替代其他证据。

## 来源交付索引

完整 PDF 生成另按[来源交付索引](delivery-checks.md)准备逐页来源材料，运行 `validate_delivery.py`。它检查实际文件、哈希和已盘点单元的交付关系；它不把“有映射”当作“翻译正确”，也不把执行者自填的通过状态当作独立来源核验。

## 可见排版提示

使用 [lint_presentation.py](../scripts/lint_presentation.py) 的 `lint_file(Path(...))` 或 `lint_presentation(text)`。在编辑器中运行时修改顶部 `NOTE_PATH`，无需命令行参数。

返回每条提示的 `rule_id`、`line`、`code`、`excerpt`、`message`。检查范围包括裸邮箱、裸 DOI、裸网址、可见连接线、常见带单位量、百分数和中外文间距；Rich Table 的所有工作表可见字段都参与扫描。Rich Table 提示行号指向所在数据块，不虚构单元格源码行号。

新增的定向提示分别检查同组多面板调用被拆链、末尾原条目标题前缺分隔线、图内表新锚缺来源 token、显示公式尾部标点，以及数学环境中的数字连接线。`MATH_RANGE_OR_SUBTRACTION` 要求按来源区分范围和真实减法；只把范围改成 `\text{-}`。已有图内表锚只登记兼容提示，不据此迁移已核实的 ID。

代码、YAML 属性、链接目标、数学环境有各自的排除规则。编号标题中规定的分隔空格不作为中外文多余空格。常见公历年份及公历年份范围不作为时长处理。这是有明确覆盖范围的启发式提示；日期、词义或复杂 Markdown 仍可能需要逐处判断。每条提示修正或登记有来源依据的解释后再验，不对全文进行盲目的字符替换。没有提示只表示这些模式未发现问题，不能据此认定所有格式或内容通过。
