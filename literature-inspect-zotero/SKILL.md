# 读取条目与全文状态

## 必要输入

- 库与条目 key，或能唯一定位条目的条件。
- 读取[交接约定](../literature-zotero2obsidian/references/pipeline-contract.md)；涉及项目路径、模板、工具或阻断级别时读取[项目配置](../literature-zotero2obsidian/references/project-profile.md)。

## 执行步骤

1. 通过 [zotero-skills](../zotero-skills/SKILL.md) 定位条目。
2. 遍历字段、子项、附件、批注与集合分页。
3. 依据文档内容确认全文版本及附件角色。
4. 核对关联笔记、人工内容和重复候选。

## 约束

- 多匹配时逐项核对身份与版本。
- raw 保留接口返回的完整字段及作者角色。
- 集合记录直接归属及逐级父链的库、key、原名。
- 标签和搜索视图不参与分类。
- 父链缺失、成环或分页未尽时记录不完整。
- 附件清单覆盖全部格式。
- 附件可用性须核对 linkMode、声明 MIME、签名、路径、非空可读性与格式有效性。
- 区分主全文、SI、快照、仅链接及其他附件。
- 按指定版本的题名、作者及内容选择全文；候选难以区分时列差异并阻断。
- 不同版本的图表和书目分别保留。
- 结合声明语言及开头、中部、结尾正文样本判定 zh/non-zh/mixed/unknown。
- 题名、摘要、书目或汉字外观不能单独决定正文语言。
- 扫描件无样本时记 provisional/unknown；收到第 2 步新证据后仅更新语言判断与历史。
- 只读检查，不下载附件或改动条目、集合、笔记。

## 产物

- item.json；run.json 的身份与本步状态。

## 验收标准

- [ ] 已获数据可追溯到原记录。
- [ ] 缺失信息区分原记录为空、无法读取和未读完。
- [ ] 每个附件都有角色和可用性记录。
- [ ] 主全文选择有版本证据或明确阻断原因。
- [ ] 语言结论附正文定位或待核原因。
