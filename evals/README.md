# 技能独立执行测试

单元测试检查脚本行为。技能执行测试检查模型能否按技能完成实际任务，两种证据分别记录。

已完成记录：[2026-11-23 低推理模型测试](2026-11-23-low-model.md)，两轮文献产物均未通过验收。

## 固定输入

每次执行使用独立目录，内含冻结的技能文件、原始附件和空输出目录。记录每个技能文件的 SHA-256。原始附件按角色命名，例如 main.pdf 与 supplement.pdf。

执行快照只暴露任务所需的 `literature-*` 技能目录、`template/` 和必要依赖。`evals/`、历史候选、评分记录以及根 README 中的案例结果留在评审侧；不要把带有历史测试答案的完整仓库直接作为后续盲测输入。

验收样例只提供给评审者。执行代理不接收样例内容、预期数量、已知缺陷、其他代理输出或评审结论。修订后的测试使用新代理，不沿用旧执行上下文。主控不补写候选后再把结果归因于被测模型。

## 执行配置

记录实际请求的模型标识与推理强度。本次低能力压力测试使用 `gpt-5.6-luna`、`low`；这是一项已运行配置，不代表对所有可选模型的能力排名。

使用不继承对话的子代理。执行代理不再创建其他代理。基线与修订版使用相同任务文字，只有输入、输出和技能快照路径不同。

任务文字模板：

```text
请使用 <技能快照>/literature-zotero2obsidian/SKILL.md 及其引用的子技能，
将 input/main.pdf（主文）和 input/supplement.pdf（补充材料）整理为完整的
Obsidian 中文文献笔记候选，附所需图件和处理记录。
本次仅生成候选，不向真实 Zotero/Obsidian 写入。
没有提供实际文献库访问；缺少库级信息时如实记录，继续完成能够根据 PDF
完成的候选内容。模板与术语表位于技能快照的 template/。
仅使用本执行目录中的源材料和技能。不要创建子代理。
请实际完成处理，不只写方案。
候选保存在 output/candidate.md，状态报告保存为 output/execution-report.md。
```

Python 代码遵循任务中的路径、进度与脚本接口要求。模型执行过程中的中断须保留原因；中断运行不作为一次完整成功或失败结果。不得隐瞒失败后挑选较好的重试。

## 独立评审

从用户样例与原始附件建立可复用的单目标验收表。每个目标包含 ID、通过条件、来源定位、候选证据、结果和严重程度。

| 结果 | 含义 |
|---|---|
| pass | 有证据支持该目标 |
| fail | 该目标有具体缺失或错误 |
| blocked | 验证所需的真实环境或外部数据不可用 |
| not_tested | 本次没有完成该项核验 |

下列检查分别形成目标：

- 主文内容完整性。
- 补充材料内容完整性。
- 作者与单位的对应关系。
- 公式的数学内容。
- 主文书目的逐条交付。
- SI 书目的逐条交付。
- 文内引文的对应关系。
- 每个表格的结构与原文对应关系。
- 每张工作表的锁定状态。
- 每张工作表的主题。
- 每幅图的面板完整性。
- 每幅图的图外内容排除情况。
- 原始附件的只读保护。
- 缺失环境的如实报告。

上述是检查维度索引；具体表格单元、公式、段落或图像要素仍逐项设目标。图像须打开源页和候选资源进行视觉核验，不能仅比较数量或尺寸。原文自身的差异单列，不擅自更正原文以追求表面一致。译文不要求逐字相同；新的兼容锚点按实际引用落点判定。既有 ID 保护用修复场景另验。

静态检查零错误不能替代内容验收。通过项数量不是等权质量分。只有一篇期刊论文及一份 SI 的执行不能证明 DOCX、电子表格、视频、其他文献类型或真实库写入已经通过。

## 规则粒度审阅

每条约束采用 `前缀-C编号`，每条验收采用 `前缀-A编号`。不同可独立失败的目标必须拆开；条件、值域和替代实现方式可以限定同一目标。拆分时对照原条目保留条件及例外。旧条目到新 ID 的映射供语义保全复核。

仓库检查器验证规则 ID、重复 ID、所属技能和复选框结构。它不根据标点或连接词推断语义原子性；语义判断需独立逐项审阅。

## 保存证据

执行清单记录模型配置、技能文件哈希、源文件哈希和候选哈希。评审保留原始候选，不覆盖模型输出。用户附件、完整笔记和生成图件不随仓库测试记录公开上传；仓库仅保存测试方法及必要汇总，完整评审作为独立交付保存。
