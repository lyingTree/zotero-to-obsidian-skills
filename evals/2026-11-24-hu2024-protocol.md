# Hu 2024 九配置独立执行协议

## 本次问题

判断同一版技能在 `luna`、`terra`、`sol` 的 `low`、`medium`、`high` 下，能否从正文 PDF 与补充 DOCX 生成达到用户 Markdown 标准的完整笔记。

模型标识固定为 `gpt-6-luna`、`gpt-6.1-terra`、`gpt-6.2-sol`。这是不同产品版本的实际配置比较，不能当作同一代模型的受控架构实验。技能固定于 `f410b04a208259382ac88c9d9d92f31108619fab`。本次评测工具与结果文档的后续提交不改变执行快照。

## 输入与独立性

`model_matrix.py` 从指定 Git 提交读取技能与模板，建立九个目录。它不调用模型，也不产生模型质量结论。宿主另外发起九次真实 `collaboration.spawn_agent` 调用，每次明确配置模型、推理强度和 `fork_turns="none"`。

每个执行者只接收本目录位置及相同的 `task.txt`。输入为同一份正文 PDF、同一份补充 DOCX 和同一份技能快照；不提供标准 Markdown、历史结果、其他候选、预期对象数量或评审结论。快照不包含根 README 和 evals。每个执行者不得创建其他代理，不使用网络获取同篇文献的现成译稿。

隔离是独立上下文、目录和明确的读取限制；宿主文件系统仍然共享，不宣称操作系统级隔离。结束时检查原始文件、技能和任务提示的哈希。未经观察的访问行为不能凭哈希宣称不存在。

## 验收原则

标准 Markdown 确定所需内容与排版；事实和数学含义以原始正文及补充材料为依据。原始文件中的歧义单列。标准稿中可确认的错误不要求复刻。没有给执行者的真实库路径、库内匹配和 Zotero 条目 ID 不作为离线可推导内容。

允许以下等价变化：

- 不改变含义的中文措辞。
- 不遗漏信息的句子拆分或合并。
- 指明来源疑点或翻译选择的合理译注。
- 指向正确对象的兼容锚点命名。
- 对应同一资源的合理文件编码与文件名。

译注不能补造来源事实，不能代替缺失段落，不能掩盖错误数值或公式。说明原文歧义时保留原始依据。

只核对 Markdown 文件及其引用资源。应用界面、点击行为、插件显示、阅读视图和原生缓存不进入本次验收。

## 单目标检查

以下是实例化检查的规则，每个实际段落、对象或字段各有独立 ID。不得把一个整篇汇总项替代实际对象检查。

| 类别 | 一个检查的目标 |
|---|---|
| 元信息 | 一个来源字段转写正确 |
| 作者 | 一名作者的姓名完整 |
| 作者单位 | 一名作者的单位映射正确 |
| 通讯身份 | 一名通讯作者的标记有来源依据 |
| 段落 | 一个来源段落的信息未缺失 |
| 译义 | 一个来源论断的含义未改变 |
| 数值 | 一个数值保持正确 |
| 单位 | 一个量的单位保持正确 |
| 公式 | 一个公式的数学关系正确 |
| 公式号 | 一个公式的原编号正确 |
| 表格 | 一个单元格的内容正确 |
| 表格合并 | 一个合并范围正确 |
| 表格锁定 | 一张工作表的 locked 为 true |
| 表格主题 | 一张工作表的 theme 为 grid |
| 图像 | 一个来源面板完整保留 |
| 图像边界 | 一幅图的一条边未裁掉图内信息 |
| 图像正文 | 一幅图不混入图外正文 |
| 题注 | 一条题注的信息完整 |
| 书目 | 一条参考文献的一个身份字段正确 |
| 引文 | 一次正文调用指向正确书目 |
| 对象链接 | 一次图表公式调用指向正确对象 |
| 资源 | 一项本地引用可解析到实际文件 |
| 结构 | 一个章节处于要求的位置 |
| 排版 | 一处明确格式要求得到满足 |

脚本可以报告结构、绑定、链接和数量的客观线索。它不能授予翻译语义通过，不能把相似度、长度或“检查器零错误”当作整篇通过。

技能要求的处理记录另报完成情况，区分 Markdown 内容质量和全流程文件记录是否闭合。单纯过程未观察不臆断模型执行失败；文件记录缺失按实际可见缺项报告。

## 结论与重测

- `pass`：适用的必需目标均有证据通过。
- `fail`：至少一个必需目标存在已定位的缺失或错误。
- `not_tested`：尚未完成所需核验。
- `blocked`：核验所需外部条件实际不可用。
- `interrupted`：执行被环境或宿主中断；与正常完成但质量失败分开。

原始候选保持不变。评审不向执行者补发缺陷提示，不补写候选后归功于原模型。重试使用新运行 ID，旧结果保留。修改技能后重新冻结，并重新执行需要比较的配置；不同版本不拼成同一矩阵。

九格每格一次只能证明本篇、该次执行的表现。如果出现全通过配置，优先对最低通过配置独立复跑。只通过一次不称为稳定门槛；高强度的一次失败也不能证明它普遍弱于低强度。

## 留存

公开仓库保存通用脚本、协议与结果摘要。用户原文、标准笔记、候选全文和提取图件不提交公开仓库。私有交付保存模型启动配置、输入哈希、候选哈希、逐项缺陷定位和原始输出。计费、令牌量、完整内部执行轨迹等宿主没有返回的字段不估造。
