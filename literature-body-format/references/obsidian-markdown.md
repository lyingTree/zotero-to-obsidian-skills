# Obsidian Markdown 检查表

先按下表识别本次范围内的语法。按原文和笔记意图区分可见字面文本、预期格式和结构化内容。检查正文、题头、题注、译注、脚注、书目、补充材料、链接显示文字，以及实际按 Markdown 渲染的字段。重点检查行首和行尾、空行及缩进变化、紧邻中英文或标点、跨行定界符、嵌套和相邻块。

| 解析范围 | 检查对象 | 验收证据 |
| --- | --- | --- |
| 段落与块结构 | 空行、软/硬换行、缩进、ATX/Setext 标题、分隔线、有序/无序/任务列表、引用及嵌套 callout | 块类型、层级、边界、换行与折叠状态符合意图。检查数字后的 `.` 或 `)`、下划线行及 `---` 的多义性。 |
| 行内格式 | `*`、`_`、`**`、`__`、`~~`、`==`（含颜色标记）、反引号、反斜杠、HTML 实体 | 字面符号完整且无多余反斜杠。预期格式范围准确，相邻文字保持可见且格式正常。 |
| 链接、标签及嵌入 | Markdown 行内/引用式链接、自动链接、`[[…]]`、`![[…]]`、`![…](…)`、标题与块引用、别名与媒体尺寸、`#标签/子标签`、URI | 显示文字与 `href` 分开核对。邻接标点留在链接外。用原生缓存校验适用的内部目标、标题、块 ID、标签与资源。 |
| 注释、脚注及 HTML | `%%` 行内/块注释、`<!-- … -->`、`[^id]`、`^[…]`、HTML 标签及属性 | 注释开合及隐藏范围正确，脚注引用与定义对应，续行归属正确。核对 HTML 块与 Markdown 的解析边界；行内脚注用阅读视图或支持它的原生渲染验收。 |
| 代码、公式及图表 | 行内代码、围栏或缩进代码块、`$`、`$$`、LaTeX、Mermaid、GFM 表格 | 定界符配对，后续文本未被吞并。代码内部、数学上下标及反斜杠保持原意。核对表格列界、单元格、公式与图表的实际渲染。 |
| 属性与插件 | 起始 YAML、Rich Table、其他实际出现的插件围栏、内联标记和可嵌入格式 | 按对应解析器核对类型、值及标记边界。普通数据照录。只有插件按 Markdown 渲染的字段才应用该层的转义，并回读序列化后的值。插件未启用或无法渲染时记录具体位置和状态。 |

## 转义与复核

1. 只转义所在解析层会误读的字面定界符。使用该层识别的最小写法。例如 `356-WTs\_E及356-WTs\_W`、`\#字面标签`、`1\. 开头的文字`、`1\) 开头的文字`、`\%\%说明\%\%`。普通文本中标识符的字面 `_` 统一转义。表格内的字面竖线可用 `\|` 或 `&#124;`，原生表格内的链接别名或嵌入尺寸分隔符按表格层转义。代码示例可用足够长的反引号包围。遇到不确定的语法先用实际解析器验证。
2. 保留有意的语法。处理链接显示文字时保护目标、路径、查询参数、片段及锚点 ID。代码、数学、HTML、YAML 和插件数据各用自己的转义规则。禁用全局替换；嵌套解析时先确定每层接收的实际字符串。
3. 比对源码和解析结果。源码检查记录位置、原显示文字、预计结构及保护内容。对修订稿复跑同一处理，结果无新增差异。渲染复查改动处及相邻结构，确认文字、顺序、格式起止及对象完整，尤其检查另一端定界符或后续正文是否被吞并。能复现误触发时保留修复前后证据，覆盖行首、跨行、同段多标识符和紧邻中文的适用情况。
4. 证据分记源码、原生离屏渲染、阅读视图、缓存和插件结果。仅对实际覆盖的部分判通过。遇到清单外或版本、设置、插件特有语法，查对应文档与本库启用情况，渲染最小样例后按同一标准验收。
