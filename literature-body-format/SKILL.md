# 规范全文排版

## 必要输入

- 当前候选稿、模板、对象清单与资源规划。
- 读取[交接约定](../literature-zotero2obsidian/references/pipeline-contract.md)；涉及项目路径、模板、工具或阻断级别时读取[项目配置](../literature-zotero2obsidian/references/project-profile.md)。

## 执行步骤

1. 依原文章序整理标题、段落及书目。
2. 按对象清单排图、表和公式。
3. 核对结构变化，向第 9 步交接受影响的旧调用。

## 约束

- 沿用第 7 步题头，保留唯一原题 H1。
- 有摘要时，在题头之后、正文之前单独一行写 `## 摘要`。标题仅含“摘要”二字，无编号、冒号或加粗。摘要首段紧接下一行，保留摘要内容和分段，移除段首旧摘要标签。原文无摘要时省略该节。
- 摘要后直接接正文。正文自首个 H2 起按 `1`、`1.1`、`1.1.1` 连续分级编号，覆盖附录、参考文献与补充材料。摘要和「Zotero原条目」标题不参与编号。保留原层级与章序，记录新旧标题映射。
- 题注按模板加粗，关键词只存 YAML。
- 仅移除已确认的重复目录、封面出版说明与人工页码标记，每处记录依据。
- 保留有效脚注、页码引用、资助、致谢与附录。
- 原刊正文脚注保留原编号、调用位置和注文。调用写 `<sup>1</sup>`，注文就近另起引用块，首行写 `> <sup>1</sup> 注文`，续行加 `> `。仅转换已核实的脚注标记，保护数学上标和型号。已有 Obsidian 脚注链接时保留其跳转能力。
- 译注独立写为 `> 译注：…`。
- 按 [Obsidian Markdown 检查表](references/obsidian-markdown.md)区分字面文本、预期语法和各自的解析环境。扫描本次范围及相邻块，重点检查行首、跨行、嵌套及紧邻中英文和标点的组合。逐处处理误触发的定界符，普通文本中标识符的字面 `_` 写作 `\_`。转义须幂等，保留预期格式、链接目标、锚点与结构化数据。插件字段按实际解析方式处理。
- 扫描可见文本中的裸网址（含 `www.`）。核对目标后写为 `[原显示文字](<完整URL>)`，把括号、标点和相邻正文留在链接外。保留目标的协议、路径、查询参数和片段。仅有域名时核实或注明所用协议。保留边界正确的已有链接。跳过代码、公式、YAML 属性和资源路径。
- 可见正文段间恰一空行，避免连续空行。
- 标题前留一空行，标题后紧接内容；检查全部标题层级。
- 中文与数字、拉丁字母或行内数学间去多余空格，保留英文词间、数值与拉丁单位间及语法所需空格。
- 仅定点改空白，保护结构缩进、脚注、插件块与代码。
- 显示公式单独成块。与前面的引导句、标题或其他块之间恰一空行，本规则优先于标题后紧接内容的通则。已有公式锚顶格独占闭合 `$$` 的下一行，两者之间零空行。公式块结束后与后续内容之间恰一空行，有锚时从锚后计。
- 原图与中文题注就近排列。新增或复用的 PDF 图像须符合[裁剪与验收规则](../literature-fulltext-extract/references/figure-crop.md)，不以整页截图代替。
- 图内文字、色标保持原样，不另作转录或解释。
- 正文图和补充图均先嵌入图片，图片行尾两个空格硬换行，下一行紧接题注。alt 只用简短图号或留空。
- 图片题注规范为 `**图N：** 题注正文`；补充图用 `**图SN：**`。
- 题注只直译，原文面板问题如需说明，在锚后另起一句事实性译注。
- 行内图表调用保留正文形式。
- 先核对原文版面。仅原文有表格时转为 Rich Table；原文段落或列表保留其结构。既有笔记若自行制表，按原文恢复对应内容。
- 表题用 `**表N：**` 写入 `title`。表下注、表格脚注及表内符号释义写入同一 Rich Table 数据块的顶层 YAML 字符串 `footer`。多段用 `footer: |-` 并保留原顺序。块外不重复题注或表注，表注不计入 `rows`。
- 探测 rich-table 插件 manifest 的 id 与 version；插件缺失或不兼容时阻断该表。
- 表只用 rich-table 数据块，要求 version 2、columns、rows、grid 主题及 locked 为 true。
- columns 和 rows 用块状 YAML 逐条展开，保留列 id/name 与行 id/cells，禁用 flow 式数组。
- 逐表回读 rows 非空且行数等于源表，拒绝管道表、HTML 表和图片表替代。
- 表格单独成块。已有表锚 `^tbl-…` 顶格独占闭合围栏的下一行，两者之间零空行。表锚后与后续内容之间留一空行。保留已有 ID，缺失或归属不明的表锚交第 9 步。
- 正文、题注、补充材料和表格中的数学表达式整体用 LaTeX，保留上下标、重音、运算符及原编号。
- 带单位的量整体置于同一数学环境，数值与直立单位间用细空格，如 `$28\,\mathrm{m\,s^{-1}}$`。
- 笔记可见文本的连字符、范围连接线和表格缺项标记统一用 ASCII `-`（U+002D）。覆盖题头、正文、题注、表格、参考文献、补充材料和链接显示文字。保护 URL、路径、锚点 ID 和原图。Rich Table 缺项用字符串 `'-'`。
- 范围、正负号、乘积、角度和百分号随量排入公式。公式中的范围连接线用 `\text{-}`，减号保留 LaTeX 运算语义。
- 表头已给单位时只格式化对应量值，保留列单位、原精度及算例编号。
- 排除日期、UTC 时刻、文献与图表编号、DOI、链接目标及路径；已有正确公式直接复用。
- 显示公式主体与 `\tag{…}` 之间只留必要的 LaTeX 结构命令和空白。无编号公式检查闭合分隔符前，多行公式检查最后一个公式行及闭合命令前后。移除冗余标点、重复编号与误混入的文字，正文所需标点归入正文。保留数学分隔符、小数点、省略号、`\left.` / `\right.` 等有效语法及原 `\tag{…}`。用途不明时对照原文上下文。
- 公式原号在公式同行右侧，保留已核实 tag；无号公式不造号。
- 保留稳定锚点，新建导航交第 9 步。
- 主文书目标题写作 `## N 参考文献`，`N` 为实际 H2 节序号。补充书目写作 `### M.K 参考文献`，`M` 为补充材料章号，`K` 为实际 H3 节序号。编号与标题用一个半角空格分隔，如 `## 10 参考文献`、`### 11.3 参考文献`。
- 补充材料统一章名，整章排在主文全部内容（含主文参考文献）之后、「Zotero原条目」之前。按最终章序编号，迁移受影响的章节链接。
- 参考文献按原文顺序每条一项，以 `1. …` 编号，紧接标题。
- 书目条间及条内无空行，列表与其后标题之间留一空行。
- 逐条登记书目顺序、原标签和现有块 ID，保留作者—年份引文制。将缺失或不符合 `^ref-N` 的条目及已知调用交第 9 步处理。
- 旧书目脚注转列表时保留完整文本与 ID 映射；真实脚注不转。
- 只移除有证据的附加题名中译；保留中文书目与必要括注。
- 书目锚点缺失、不合规或调用受影响时，须通过第 9 步书目锚点验收后提交。

## 验收标准

- [ ] 文本、数字、对象及书目数量的变化都有来源依据。
- [ ] 有摘要时，源码恰有一处 `## 摘要`，Obsidian 将其解析为 H2。下一行是摘要首段，段首无残留摘要标签，摘要内容和分段完整。原文无摘要时，候选稿无摘要节。
- [ ] H1 为原题。正文首个编号 H2 为 `1`，参与编号的标题逐级连续。标题后紧接内容，首块为显示公式时留一空行。受保护的语法块完整。
- [ ] 书目标题源码与原生解析均符合 `## N 参考文献` 或 `### M.K 参考文献`。节序号在同级连续，首条紧接标题。纯「参考文献」、错号或附加文字均不通过。按第 9 步核对受影响的章节链接。
- [ ] 主文含参考文献全部结束后才出现补充材料。最后一个 H2 是「Zotero原条目」链接标题，按[篇内链接验收](../literature-internal-links/SKILL.md#验收标准)核对。
- [ ] 按检查表复核源码差异、转义幂等性和受影响的解析结构。用 Obsidian 阅读视图或原生离屏渲染逐处核对改动及相邻块的可见文本、格式范围和对象。内链与锚点用原生缓存核对落点，外链核对实际 `href`，插件字段用相应插件核对实际显示。记录各检查的证据与覆盖范围，缺少对应环境时标待验并注明位置。
- [ ] 对照输入逐量核对数值、单位及幂次、符号和范围；检查遗漏的裸单位与拆开的数学环境。
- [ ] 逐块检查单行和多行显示公式的源码。公式前恰一空行，有锚时闭合 `$$` 与锚相邻，块后有内容时恰一空行。按[篇内链接验收](../literature-internal-links/SKILL.md#验收标准)核对锚点范围。
- [ ] 逐块检查有编号、无编号及多行显示公式的末尾，确认无冗余字符。对照差异核对数学含义、编号和锚点，渲染抽查单行与多行公式并记录未决项。
- [ ] 可见文本中的连字符、范围连接线和缺项标记均用 ASCII `-`，无 U+2013 残留。公式范围与减号语义正确。
- [ ] 图表公式已逐项对照原文。逐幅核对最终嵌入图与[裁剪视觉验收](../literature-fulltext-extract/references/figure-crop.md)记录一致，图片在上，题注紧接在下。
- [ ] 逐条核对正文脚注的 `<sup>`、引用块、编号和链接目标。渲染时上标及引用块边界正确，数学上标和型号未误改。
- [ ] 逐表解析 YAML，确认表注完整且仅位于所属表的 `footer`，正文无重复表注，数据行数与源表一致。用已启用的 Rich Table 核对表尾显示及相邻块。
- [ ] 逐表核对插件、实际行数及源表行数。检查源码中闭合围栏后恰一个换行即为顶格独占一行的 `^tbl-…`，表锚后有后续内容时恰一空行。有空行夹在围栏与锚之间、缺锚、错绑或重复 ID 时，修复或交第 9 步并在提交前复验。
- [ ] 既有调用已保留或完成迁移。
- [ ] 离屏渲染和实际界面验收分别记录。
